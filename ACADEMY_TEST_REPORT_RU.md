# Протокол проверки SHINOBI ACADEMY V1

**База:** присланный `shinobi-arena-main (3).zip`; добавление нового локального onboarding-модуля.

## Автоматизированный интерактивный прогон

- Desktop viewport **1366×768**: открытие через стартовый экран; активный жребий; KEEP (включая ошибочный PASS), PASS, Team 7, свиток, арена, дуэль, завершение; переход к выбору режима. Успешно.
- Mobile portrait **390×844**: аналогичный полный сценарий. Успешно.
- Compact phone **320×568**: аналогичный полный сценарий. Успешно.
- Mobile landscape **844×390**: аналогичный полный сценарий. Успешно (внутренняя прокрутка).
- Повторно 320×568 и 1366×768 после изменений визуала и подведения к игровому действию — успешно.
- В 320×568 проверено, что кнопка «Показать действие» прокручивает игровое действие в область просмотра; `scrollTop` увеличился с 0 до 290 в тесте.
- Проверено, что флаг завершения старого слайдового обучения сам по себе не обходит новую Академию.
- На перечисленных прогонных разрешениях отсутствуют pageerror JavaScript, корневое горизонтальное переполнение. Активные этапы завершаются через настоящие нажатия Playwright.
- Для шага 6 итог дуэли возвращён исходным `resolveCombat()`, не подставлен готовый ответ.

## Интеграция прежней игры

- Рабочая сцена предыдущего расширенного тренинга R33/R34 запущена после Академии: учебный жребий, переход к драфту 5×5, отображение подсказок и кнопок.
- Проверен обратный выход из расширенного тренинга: значение `r20ExportProfile()` до и после сценария совпадает.
- Статическая проверка JS: `node --check` игрового скрипта и скрипта Академии выполнена без ошибок.

## Что не тестировалось / границы доказательств

- Реальные физические iPhone/Android, WebView VK/OK и iOS Safari, включая поворот/виртуальную клавиатуру.
- Реклама, авторизация, хранилище, сетевые сбои и нагрузка в настоящем SDK VK.
- Онлайн-матчмейкинг и сервер: соответствующий онлайн-код в присланной базе отсутствует.
- Решение модератора VK/OK — подтвердить принятие по локальному тесту нельзя.

### Техническая методика

В изолированной среде прямое открытие страниц браузером было заблокировано. Поэтому для прогона использованы DOM из исходного HTML, оригинальные CSS и оригинальные JS из архива, последовательно добавленные в Chromium через Playwright. Изображения подставлены из исходных asset-файлов через data URL исключительно для снимков тестового стенда. Это выполняет реальный JS-код, но не заменяет проверку корректности сетевой загрузки на GitHub/VK.
